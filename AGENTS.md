# AGENTS.md

Flutter app (Material 3) for the Scénická žatva festival / javisko.sk. UI text is Slovak (`sk_SK` date formatting). `provider` + `go_router` state/routing; Firebase (Auth, Realtime Database, Messaging, Storage, Analytics) is the backend.

## Commands

- Analyze/lint: `flutter analyze` (default `flutter_lints`, no custom rules)
- Test: `flutter test` — **`test/widget_test.dart` is a stale default counter smoke test and does not match the current app; do not treat a failing `flutter test` as a regression.**
- Regenerate Hive adapters after editing models that use `@HiveType`/`@HiveField`: `dart run build_runner build --delete-conflicting-outputs`. The committed `*.g.dart` and `lib/hive_registrar.g.dart` must stay in sync (register adapters in `main.dart`).
- Web build + deploy: `flutter build web` then `firebase deploy --only hosting` (hosting serves `build/web`).

## Firebase

- Default project: `scenickazatva-343517` (`.firebaserc`). `lib/firebase_options.dart` and `android/app/google-services.json` are committed and generated by `flutterfire configure` — don't hand-edit.
- Cloud Functions live in `functions/` (Node 22): one scheduled function `checkNewArticles` polls the WordPress REST API (`javisko.sk/wp-json`) and sends FCM notifications to topic `magazine_updates`. `firebase deploy --only functions`; local emulation `npm --prefix functions run serve`. `firebase.json` predeploy runs eslint.
- `firebase_functions/` at repo root is an empty leftover — ignore it; use `functions/`.
- Realtime DB (not Firestore) holds events, info posts, user profiles (`users/{uid}`, role assigned from `appsettings/predefinedRoles`), and festival config (`appsettings/festivals` + `appsettings/defaultfestival`). The active `Festival` is selected from `AppSettings.defaultfestival`, not fetched directly.
- User role writes must go through `UserData.toSafeJson()` (`lib/requests/FirestoreService.dart:165`) to prevent self role-elevation.

## Data architecture

- `lib/requests/` are the services: `FirestoreService.dart` (auth + user records), `WordPressService.dart` (news/magazine via `wordpress_client` with Hive-backed HTTP cache), `NotificationService.dart`, `ImagePrecacheService.dart`.
- `lib/providers/*` are `ChangeNotifier`s wired in `lib/main.dart`'s `MultiProvider`. `EventsProvider`/`InfoProvider`/`NewsProvider` depend on both user role and festival/settings via `ChangeNotifierProxyProvider`.
- `lib/models/` contains Hive-typed models (`Festival`, `AppSettings`, `Ad`) plus plain models. `lib/widgets/` is currently empty; shared widgets are inline in views/pages.

## Repo gotchas

- Do **not** `git add .`: the working tree has many untracked dirs (`.agents/`, `android/`, `android_backup/`, `functions/`, `web/splash/`) and accidental root files (`signal-desktop-keyring.gpg`, `signal-desktop.sources`, `skills-lock.json`). Stage files explicitly.
- Firebase agent skills are vendored in `.agents/skills/` (managed by `skills-lock.json`); load them for Firebase work.
- CI is external (Codemagic, triggered by git tags), not configured in this repo.

## Workflow

- `develop` is the default branch; `master` holds production. Feature/bugfix branches: `f/...`, `bf/...`. Merge PRs into `develop`.
- Releases: PR `develop` → `master`, bump `version:` in `pubspec.yaml`, then `git tag vX.Y.Z` (triggers Codemagic build). See README.md for the full flow.

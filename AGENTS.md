# AGENTS.md

Flutter app (Material 3) for the Scénická žatva festival / javisko.sk. UI text is Slovak (`sk_SK` date formatting). `provider` + `go_router` state/routing; Firebase (Auth, Realtime Database, Messaging, Storage, Analytics) is the backend.

## Commands

- Analyze/lint: `flutter analyze` (default `flutter_lints`, no custom rules)
- Test: `flutter test` — real unit tests in `test/` (`game_test.dart` for game logic, `event_datetime_test.dart` for Event timezone parsing); there are no widget tests.
- Regenerate Hive CE adapters after editing `@HiveType`/`@HiveField` models: `dart run build_runner build --delete-conflicting-outputs`. Committed `*.g.dart` must stay in sync. **`lib/hive_registrar.g.dart` is generated but not wired up** — `main.dart` registers the three adapters manually (`FestivalAdapter`, `AppSettingsAdapter`, `AdAdapter`); a new `@HiveType` model needs an explicit `Hive.registerAdapter(...)` call in `main.dart`.
- Web build + deploy: `flutter build web` then `firebase deploy --only hosting` (hosting serves `build/web`).

## Firebase

- Default project: `scenickazatva-343517` (`.firebaserc`). `lib/firebase_options.dart` and `android/app/google-services.json` are committed and generated by `flutterfire configure` — don't hand-edit.
- Cloud Functions live in `functions/` (Node 22): scheduled `checkNewArticles` (every 30 min) polls the WordPress REST API (`javisko.sk/wp-json`) and sends FCM notifications to topic `magazine_updates`; `assignRoleOnUserCreated` + `syncRolesFromPredefinedRoles` assign roles server-side. `firebase deploy --only functions`; local emulation `npm --prefix functions run serve`. `firebase.json` predeploy runs eslint.
- **Despite its name, `FirestoreService.dart` talks to the Realtime Database, not Firestore** (the backend is entirely RTDB).
- Realtime DB holds events, info posts, game (`festivals/{id}/game`: meta fields `title`/`description`/`endsAt`, `questions/{id}`, `participants/{uid}` incl. `winner`; user submissions at `users/{uid}/game/{festivalId}/{questionId}`), user profiles (`users/{uid}`), and festival config (`appsettings/festivals` + `appsettings/defaultfestival`). The active `Festival` is selected from `AppSettings.defaultfestival`, not fetched directly.
- Security rules live in `database.rules.json` (deployed with `firebase deploy`). RTDB rules cascade top-down — shallow rules override deeper ones, so access is granted per-node, never per-field-revoked. Roles (`userRole`) are assigned by Cloud Functions; clients only write profile fields via `UserData.toSafeJson()` (`lib/requests/FirestoreService.dart`) and can never write `userRole` or read `appsettings/predefinedRoles`. Game `winner` is protected by a `.validate` rule (admin/editor only).

## Data architecture

- `lib/requests/` are the services: `FirestoreService.dart` (auth + user records; class is `authService`), `WordPressService.dart` (news/magazine via `wordpress_client` with Hive-backed HTTP cache), `NotificationService.dart`, `ImagePrecacheService.dart`, `SystemServices.dart` (url launching + analytics).
- `lib/providers/*` are `ChangeNotifier`s wired in `lib/main.dart`'s `MultiProvider`. `EventsProvider`/`NewsProvider`/`InfoProvider`/`GameProvider` depend on user role and/or festival/settings via `ChangeNotifierProxyProvider`.
- `lib/models/` contains Hive-typed models (`Festival`, `AppSettings`, `Ad`) plus plain models. `lib/widgets/` has `DynamicIcon.dart`; shared widgets are otherwise inline in views/pages.

## Repo gotchas

- Firebase agent skills are vendored in `.agents/skills/` (gitignored; managed by `skills-lock.json`); load them for Firebase work.
- CI is external (Codemagic, triggered by git tags), not configured in this repo.

## Workflow

- `develop` is the default branch; `master` holds production. Feature/bugfix branches: `f/...`, `bf/...`. Merge PRs into `develop`.
- Releases: PR `develop` → `master`, bump `version:` in `pubspec.yaml`, then `git tag vX.Y.Z` (triggers Codemagic build). See README.md for the full flow.
